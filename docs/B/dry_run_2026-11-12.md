## 3. One new fact the run produced

The host's subnet **changed between sessions**: `10.163.167.0/24` on 2026-11-11,
`10.163.208.0/24` on 2026-11-12, same machine, same campus SSID. `resolve_subnet()` therefore
picks a different /24 to sweep on different days, and the log says so explicitly.

Consequences, both already required by D-013 but now measured twice:

- On the demo network, set `WI_FI_SUBNET` explicitly (e.g. `192.168.137.0/24` for a Windows
  mobile hotspot) instead of relying on auto-detection.
- The BSSID must be captured **live** at the venue; it changed from `50:98:b8:c9:2b:e2`
  (2026-11-03) to `f4:74:88:70:c2:f1` (2026-11-11) at the same desk.

## 5. How to repeat it

The five commands in §1 are copy-pasteable on any machine with the venv installed. Use an
isolated `DATABASE_PATH`/`--db`, never `backend/attendance.db`, so the demonstration database
is untouched. Expected wall time: about one minute, dominated by the two server starts.
