WEEK 1-2: PRIORITY 1 - BLOCKERS
--------------------------------

Step 1 - Fix Face Enrollment Data Saving
  - Create backend/data/faces/ directory
  - Write uploaded image bytes to disk (not just store path)
  - Store real face embedding bytes in database (not "b"blob"" literal)
  - Test: Enroll a face via Swagger UI and verify data in database

Step 2 - Link Start and End Selfies (Two-Stage Logic)
  - Create a function to find existing "start" record for same student+schedule
  - When "end" check arrives, pair it with the "start" record
  - Add new status values: "partial" (only start done), "verified" (both done)
  - Do NOT mark attendance as fully "present" until both checks exist
  - Prevent duplicate check-ins for the same schedule session
  - Test: Enroll face, do start check, do end check, verify both are linked

Step 3 - Enforce Schedule Time Validation
  - Call get_schedules_for_now() in the attendance check router
  - Reject attendance if current time is outside the schedule window
  - Use ATTENDANCE_CHECK_WINDOW_MINUTES for grace period before/after class
  - Test: Try checking in outside class hours - should be rejected

Step 4 - Fix Mobile-Backend Data Contract
  - Update Flutter AttendanceResult model to match backend's response fields
    (id, student_id, schedule_id, check_type, confidence, wifi_verified,
     status, timestamp)
  - OR change backend response to match what Flutter expects
  - Test: Capture photo on phone, upload, see correct result on screen

At the end of Week 2: The system should be testable end-to-end for the
first time using Swagger UI (backend) and a real Android phone (mobile).
