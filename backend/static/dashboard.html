System Architecture How the three pillars work together
Wi-Fi AP Face Recognition Two-Stage Logic Attendance

Wi-Fi AP Detection

Scans classroom network via ARP to verify the student's device is physically present on the correct access point. Uses Npcap/Scapy.

Face Detection & Recognition

YOLOv8-face detects faces, InsightFace ArcFace (buffalo_l) generates 512-D embeddings. Cosine similarity threshold: 0.5.

Two-Stage Attendance

Start of class: status = "partial". End of class: finalizes to "verified" (Wi-Fi ok on both) or "face_only" (no Wi-Fi).

SQLite Database

Stores students, faces (embeddings), schedules, attendance records, and AP logs. Rollback-safe transaction logic.

Flutter Mobile App

Android/iOS app for student selfies. Captures face images via camera for enrollment and attendance check-in.

FastAPI Backend

Python web server connecting all components. Endpoints for face operations, attendance logic, Wi-Fi scanning, and data export.

Attendance Flow

1. Wi-Fi Check
ARP scan for student MAC
2. Start Selfie
Face detection + recognition
3. Partial Status
Wi-Fi: OK | Face: matched
4. End Selfie
Second face match + Wi-Fi re-check
5. Verified!
All conditions satisfied
Key Rule: Attendance is granted ONLY when all 3 conditions are met: correct Wi-Fi AP + valid class time + both selfies matched.
